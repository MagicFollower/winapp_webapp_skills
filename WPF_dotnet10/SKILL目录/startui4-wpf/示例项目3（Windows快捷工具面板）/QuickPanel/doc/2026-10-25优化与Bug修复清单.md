# 2026-10-25 优化与 Bug 修复清单

## 应用版本升到 1.0.0

- 问题：交付版本仍是 `0.1.0`，需要升到 `1.0.0`（`FileVersion` 随之 `1.0.0.0`）。
- 成因：版本号只有 csproj 的 `<Version>` 一处真源，exe 的 `FileVersion` / `ProductVersion` 由它派生；界面「关于」走反射读程序集版本，不需要另改。
- 核心修复方案：改 `<Version>1.0.0</Version>`，同步 README 速查与 T0Level 的「当前版本」表述；带日期的历史实测输出保持原样（它们是当时的记录）。重新打包后按 `FileVersion` 守门比对。
- 改动点：`app/QuickPanel.csproj`、`README.md`（版本速查行）、`doc/运行与构建（T0Level）.md`（发版流程里的当前版本）；是否动 `lib/`：否。`publish_no_runtime\` 里的旧产物仍是 `0.1.0.0`，未重新打包。

## 端口脚本改为打进 exe（替换外部 app_script 引用）

- 问题：上一版以 `Content` 把 `app_script\port_killer_v3.cmd` 拷到 exe 旁边，发布目录会多一个文件夹；要求脚本随 exe 一起交付、不留外部文件。
- 成因：`Content` + `CopyToPublishDirectory` 的语义就是"外置一份"；单文件发布里要让它真正躺在 exe 内，得走程序集资源。
- 核心修复方案：改为 `EmbeddedResource`（随程序集进单文件包），命令从 `app_script\…` 换成 `script:port_killer_v3`；`LaunchService` 按资源名后缀取流，按 SHA-256 前 8 位释放到 `%LOCALAPPDATA%\QuickPanel\scripts\<hash8>\port_killer_v3.cmd` 再启动——哈希目录保证升级不覆盖正在被 cmd 逐行读取的旧副本。弃了 `IncludeAllContentForSelfExtract`（会把整个应用解到临时目录，代价远超一个脚本）。
- 改动点：`app/QuickPanel.csproj`（Content→EmbeddedResource）、`app/Services/LaunchService.cs`（`script:` 解析 + 释放 + 失败文案）、`app/Services/ToolCatalog.cs`（命令与说明）；是否动 `lib/`：否。上一版"发布时外置 app_script"的打包方式由本条取代。

## 「命令与运行」新增端口占用查询与结束脚本入口

- 问题：`app_script/port_killer_v3.cmd` 已在工程里，但目录数据源没有引用它，界面上点不到。
- 成因：`ToolCatalog.Items` 是静态写死的入口表（原 90 项），新增脚本要同时补数据源条目、发布拷贝与启动路径解析；缺一条就是"点不开"或"发布后丢文件"。
- 核心修复方案：在 `run` 组加一条 `Probe=None` 的入口（带危险提示与悬浮说明）；`csproj` 用 `Content` + `ExcludeFromSingleFile` 把脚本拷到 exe 旁边的 `app_script\`；`LaunchService` 把"含目录分隔符的相对路径"按 `AppContext.BaseDirectory` 解析，缺失时给明确文案（不把应用目录硬塞进 System32/Windows 两挡探测）。弃了写死绝对路径：收藏键会随安装位置失效。
- 改动点：`app/Services/ToolCatalog.cs`（91 项 + 新条目）、`app/Services/LaunchService.cs`（`ResolveAppRelative` + 存在性检查）、`app/QuickPanel.csproj`（Content 拷贝）；是否动 `lib/`：否。顺带同步 README / T0Level 文档里的 90 项与 `SelfTest.cs` 注释为 91。
