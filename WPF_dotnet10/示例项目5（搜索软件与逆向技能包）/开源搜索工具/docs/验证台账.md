## 5. UI 帧间隙（未按原判据验证）

`--perf` 探针在查询/滚动窗口内同时记录：

```text
CompositionTarget.Rendering: frames=24  max_ms=211.5  p95_ms=206.2  over100=16  tier=2
UI 线程 10 ms DispatcherTimer: timer_frames=198  timer_max_ms=45.3  timer_over100=0
```

- `CompositionTarget.Rendering` 在本会话只有约 10 Hz；app 窗口已 `SetForegroundWindow`，`tier=2`，显示器 144 Hz。无法区分是 WPF 合成器被本会话节流，还是应用真实掉帧；因此**“0 个 >100 ms 帧”原判据未验证**，不写成通过。
- UI 线程定时器最大迟到 **45.3 ms**、>100 ms 次数 **0**，说明查询/绑定/滚动没有把 UI 线程连续占住（对照记忆中“684 ms 就够让鼠标转圈”的口径）。
- 要关闭这一项，需要在一个普通交互桌面会话（非自动化/非隐藏窗口）复跑 `--perf`，或在 CI 里用真实的 60/144 Hz 合成器；这是 M1 的遗留验证项，不是已通过项。
