## 4. 核心技术架构

```
┌────────────────────────── FinderPro.exe（UI 进程）───────────────────────────┐
│  XSkin DirectUI（XML 皮肤/xf 资源包） + GDI+ 渲染 + ATL 内嵌浏览器(ADBrowser)  │
│  分类面板(btnAllType/Image/Doc/Video/Audio/MobApp/Folder) + 预览(frmPreview)   │
│  热键(msctls_hotkey32) + 托盘 + WinInet(更新检查) + 互斥体单实例               │
└──────────────┬───────────────────────────────────────────────┬──────────────┘
               │ C++ API（隐式链接）                             │ LoadLibrary 动态加载
┌──────────────▼──────────────┐                  ┌─────────────▼─────────────┐
│ FinderFS.dll（搜索引擎核心）  │                  │ AutoUpdate.dll/CCReport.dll│
│ · NTFS USN Journal 全盘索引   │                  │ （不在安装包，运行时获取）   │
│   CreateFileW(\\.\C:)        │                  └───────────────────────────┘
│   DeviceIoControl(FSCTL_ENUM │
│   _USN_DATA / READ_USN_JRN)  │
│ · 内存索引 fileEntry 数组     │        ┌─────────────────────────────────────┐
│   + tcmalloc 分配器           │        │ 支撑组件                             │
│ · 模式匹配 build/process_     │        │ · Utility.dll：libcurl7.31.0/MD5/   │
│   match_pattern（UTF-8）      │        │   日志/线程池/崩溃上报/机器码        │
│ · 多线程排序 FSResultSortImpl │        │ · Guid.dll：GetMid 设备指纹(id.dat)  │
│ · 持久化 finder.db/filetag.db │        │ · PreviewGenerator.dll：PDF/RAR/图标 │
│ · HWND 消息回调刷新 UI        │        │ · FPdfSdk.dll：Foxit PDF 渲染        │
└──────────────────────────────┘        └─────────────────────────────────────┘
                                        ┌─────────────────────────────────────┐
                                        │ Shell 集成（COM，regsvr32 注册）      │
                                        │ FinderContext.dll(x86)/64.dll(x64)  │
                                        │ IContextMenu 右键菜单 → 启动搜索     │
                                        └─────────────────────────────────────┘
```

**搜索引擎技术要点**（对照 Everything 的同类实现）：
1. **索引建立**：`FileSystemLoadThread` 逐卷 `\\.\X:` 打开卷句柄 → `DeviceIoControl(FSCTL_ENUM_USN_DATA)` 一次性枚举全部 MFR 记录 → 内存 `fileEntry` 数组（tcmalloc 支撑海量小对象）
2. **增量同步**：`UsnJournalSync.cpp` 监听 `FSCTL_READ_USN_JOURNAL`（`UsnJournalID/FirstUsn/MaxUsn` 状态持久化），对无日志卷回退 `FindFirstFileW` 遍历并提示 `ERROR_JOURNAL_NOT_ACTIVE`
3. **检索**：`build_match_pattern` 编译查询串 → `process_match_pattern` 在内存索引上匹配（UTF-8 折叠 + `utf8_strlwr`，支持通配/大小写/全字）→ `FSResultSortImpl` 多线程归并排序 → `PostMessageW(HWND)` 回 UI
4. **状态持久化**：`%AppData%\ShanDian\finder.db`、`filetag.db`（分类标签）、`Setting.ini`、`Excluded.txt`

## 5. 签名与分发链（重要发现：二次打包证据）

| 文件 | 签名状态 | 签名者 |
|---|---|---|
| 外层安装包 exe | **NotSigned** | — |
| FinderContext/Context64/Guid/Utility/XSkin/PreviewGenerator | **Valid** | 上海宁乐科技有限公司（2012-09-03 ~ 2014-09-04） |
| **FinderPro.exe / FinderFS.dll** | **HashMismatch（签名在、哈希不符）** | 上海宁乐科技有限公司（同上） |
| **FPdfSdk.dll** | **HashMismatch** | Foxit Corporation（2010-05-04 ~ 2013-05-04） |
| **msvcp90.dll / msvcr90.dll** | **Valid，但签名者是第三方** | **天津维讯科技发展有限公司·开发部**（2013-06-24 ~ 2015-06-25） |

**推断**：原厂（宁乐）对全部组件签名后，**只有两个核心二进制 FinderPro.exe 与 FinderFS.dll 在签名后被修改**（去掉/放开"分类显示"功能，即文件名标注的"能显示分类"补丁点），并重新以 SFX（无签名）打包；CRT DLL 被换成由"天津维讯科技"重新签署的版本。FPdfSdk 的 mismatch 可能源自原发行版即存在的资源改动，但与另两个文件同列，整体指向**非官方二次打包发行**。使用该副本存在供应链完整性风险（无法验证修改内容）。

## 7. 技术栈总评

- **年代定位**：2013–2014 年国产桌面工具典型栈 —— VC9 + ATL + 自研 DirectUI + 静态 libcurl + USN Journal 索引；`NiuFinder` 项目代号与 BaseDll 共享组件库结构清晰，工程化程度较高（自动化构建、崩溃上报、日志分级）。
- **架构风格**：分层 DLL（UI / 引擎 / 基础库 / 预览 / Shell 集成），进程内单体内聚，跨位数问题（64 位 Explorer 右键）用独立 x64 COM DLL 解决 —— 主进程保持 32 位以兼容 XP 时代环境。
- **技术亮点**：tcmalloc 静态接入搜索引擎；USN 全量+增量双通道索引；自研皮肤引擎（.xf 打包格式）。
- **技术债**：HTTP 明文遥测/更新；VC6 时代的第三方 PDF SDK 无任何加固；C++03 + 手写字符串类（XString/String 双轨）；部分组件运行时才动态获取（CCReport/AutoUpdate 不在包内）。
- **合规/风险**：见 §5 二次打包证据；索引库明文存储全盘文件名；机器码收集。
