# 2026-10-27 优化与 Bug 修复清单

## 选中行上下两色、选中文字对比度不足

- 问题：结果列表选中行出现上下两段颜色；选中行的文字仍偏黑，压在蓝底上对比度不足。
- 成因：WPF 默认 `ListViewItem` 模板自带一套选中视觉，叠加宿主 `Background` 触发器后形成分层；`GridView` 的单元格文本没有跟随 `ListViewItem.Foreground` 的选中态。
- 核心修复方案：为结果行提供统一 `ControlTemplate`（单一 `Border` 铺满 28 px）+ `CellTemplate` 把每个单元格的 `Foreground` 绑定到 `ListViewItem.Foreground`；选中态统一 `ListSelected` / `OnAccent`。弃了只改 `Background` 触发器的旧写法，因为它改不掉默认模板的分层与单元格字色。
- 改动点：`app/MainWindow.xaml` 的 `ListView.ItemContainerStyle` 与四个 `GridViewColumn.CellTemplate`。`lib/` 未改。
- 验证：Release 截图选中行单色、文字白色；构建 0 错误 / 9 条 lib 自带警告；`--selftest` 退出码 0。

## 右侧预览内容贴边

- 问题：预览标题、图片/文本、底部元信息贴着卡片边缘。
- 成因：`UI4Panel` 的内容内边距属性是 `ContentPadding`，不是 `Padding`；原代码写 `Padding` 被模板忽略，只剩内层 `Margin="4"`。
- 核心修复方案：改用 `ContentPadding="20"`，并在标题/图片/文本/元信息上补 4/12/16 px 的间距。弃了继续加外层 `Padding` 的做法，因为那不是该控件的有效属性。
- 改动点：`app/MainWindow.xaml` 的结果卡与预览卡 `ContentPadding`、预览内部 `Margin`/`Padding`。`lib/` 未改。
- 验证：Release 截图预览标题/正文/元信息均有可见内边距；构建 0 错误；selftest 0。

## 结果行右键菜单、打开/定位、文件不存在提示

- 问题：结果行没有右键入口；打开/定位失败只写进设置页的 `StatusMessage`，主界面看不到；文件被删除后仍可点击，没有明确错误。
- 成因：`OpenSelected`/`LocateSelected` 没有存在性检查；没有行级 `ContextMenu`；错误没有走用户可见对话框。
- 核心修复方案：结果 `ListView` 增加右键菜单（打开 / 打开所在目录 / 复制完整路径）；右键先把命中行设为选中；`File.Exists || Directory.Exists` 先验，缺失时返回错误并用 `UI4MessageBox` 弹窗；打开/定位/双击/Enter/Ctrl+O 统一走错误提示。弃了“只写状态栏”的方案，因为用户在主界面看不到失败原因。
- 改动点：`app/MainWindow.xaml` 的 `ListView.ContextMenu` 与右键事件；`app/MainWindow.xaml.cs` 的菜单/错误处理；`app/ViewModels/MainViewModel.cs` 的 `OpenSelected`/`LocateSelected` 返回错误字符串并做存在性检查。`lib/` 未改。
- 验证：Release 环境放 `alpha.txt`/`beta.txt`/`gamma.log`，索引 4 项；选中 alpha 后删掉磁盘文件，右键 →「打开」→ 弹窗显示“文件或目录已不存在：…lpha.txt”；右键菜单 UIA 找到“打开”“打开所在目录”“复制完整路径”；关闭弹窗/应用正常。两档发布包 selftest 0。

## 选择范围后不生效

- 问题：点“范围”选中目录后，列表没有按该目录过滤；用户看到范围标签变化但结果不变。
- 成因：`SetScope` 只改标签；`FileIndex.FindDirectoryIndex` 找不到目录时（默认根只含用户目录、新建目录、被排除目录、未纳入索引的盘），`Search` 返回 `ScopeMissing`，界面只显示一行提示，用户看到的就是“没生效”。默认索引根只有 `C:\Users\<user>`，D/E 盘不在索引里。
- 核心修复方案：默认索引根改为**所有就绪的固定盘**（本机 C:\、D:\、E:\），保留 `node_modules`/`WinSxS` 等排除；`SetScope` 先查 `FindDirectoryIndex`，目录不在索引中时明确提示“请按 F5 重建或扩大索引根”，不再静默；新增 `IndexApp.exe --path <dir>` 启动即限定范围。弃了“只改标签让 Search 自己报 ScopeMissing”的旧写法，因为它把失败原因藏在底部一行。
- 改动点：`app/ViewModels/MainViewModel.cs`（`BuildOptions`/`SetScope`/`ClearScope`/`IndexRootsText`）、`app/MainWindow.xaml.cs`（`--path`）、`src/IndexCore/FileIndex.cs`（全盘扫描时跳过枚举中消失/锁定的目录，不让整次索引崩）、`app/Views/SettingsOverlay.xaml`（扫描范围说明）。`lib/` 未改。

## 查询不到 C 盘之外的内容

- 问题：全局搜索只返回 C 盘用户目录内的文件，D 盘/E 盘内容搜不到。
- 成因：M1 的默认 `BuildOptions` 只加了 `Environment.SpecialFolder.UserProfile`，没有枚举其他固定盘；引擎本身支持任意根与多卷。
- 核心修复方案：`DriveInfo.GetDrives()` 取所有 `DriveType.Fixed && IsReady` 的根，和用户目录一起建立索引；快照根与本次配置不一致时自动重建；索引根在设置页以“索引根”文本展示。弃了“默认只索引用户目录、让用户自己设环境变量”的方案，因为用户无法从界面知道 D 盘没被索引。
  - 更正（同日）：最终实现不是“所有固定盘根 + 单独用户目录”，而是只加所有固定盘根；用户目录本来就在 C:\ 根下，不再重复添加。
- 改动点：`app/ViewModels/MainViewModel.cs` 的 `BuildOptions`/`IndexRootsText`；`docs`/`README` 的默认范围说明。`lib/` 未改。

## 全盘扫描是否会损坏硬盘？

- 结论：当前扫描是**只读目录元数据枚举**——只读文件名、大小、修改时间、属性；不读取文件内容，不修改/删除被扫描盘上的文件，不做 MFT 裸卷读取、磁盘修复或格式化；唯一写入是 `%LOCALAPPDATA%\IndexApp\index.bin` 快照（外加 `.bak`）。
- 行为：首次启动对所有固定盘做一次全量枚举；之后加载快照；只有 F5/“重建索引”才再次扫描。M1 没有 USN/MFT 实时监视。
- 代价：首次全盘枚举会产生一次较集中的磁盘 I/O，时间取决于盘内文件数；频繁手动重建会增加 I/O，但正常元数据读取不会损坏硬盘。想收窄范围可设置 `INDEXAPP_ROOT=C:\Users\<user>` 或某个目录，再重建。
- 改动点：`app/Views/SettingsOverlay.xaml` 的索引说明、`README.md` 的“扫描会伤硬盘吗”一节、`doc/运行与构建（T0Level）.md` 的注意事项。`lib/` 未改。

## 追问记录：新增/删除文件会不会实时刷新？USN 增量是什么？

- 问题原文：“每次新增或删除文件，当前架构下文件列表是否会实时刷新？”以及“USN增量是什么？原理和生效流程是什么？”
- 结论：当前 M1 **不会实时刷新**；没有 `FileSystemWatcher`/USN/MFT 增量，只有启动时构建/加载快照与手动 F5/重建。新增文件搜不到，删除文件仍留在索引；重启只要快照根一致也会加载旧快照。USN 增量是 M2 的服务化方案，原理、事件映射、生效流程与回退矩阵见 `docs/USN增量-原理与生效流程.md`。
- 是否改代码：本轮只做说明与归档，没有改代码；实时增量应在 M2 以 USN + 服务实现，避免用“每次变更全量重建”冒充实时。
- 术语补充：M1/M2 是发布里程碑（Milestone），不是 Model/版本号；P0–P4 是执行阶段。定义与本项目当前内容见 `docs/续命方案-架构设计.md` §2.2.1。
