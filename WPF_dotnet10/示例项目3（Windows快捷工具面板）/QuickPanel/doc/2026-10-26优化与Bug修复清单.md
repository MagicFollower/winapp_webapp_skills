## 卡片命令条的悬浮提示改为两段式（完整命令 + 作用/原理）

- 问题：长命令在卡片里被单行省略（`TextTrimming=CharacterEllipsis`），原来的悬浮提示只显示 `DetailNote` 或通用文案，看不到命令原文；用户无法在点击执行前核对完整命令。
- 成因：数据层 `DetailTip` 只有一段说明文本；模板把 `ToolTip="{Binding DetailTip}"` 直接挂在命令条 `Border` 上，WPF 默认 ToolTip 是单段纯文本，没有"命令 / 说明"分区，也没有宽度上限与换行结构。
- 核心修复方案：
  - 数据层拆成两条：`DetailTipBody` 取 `DetailNote` → `Description` → `"点击卡片即执行"` 的回落链；`DetailTip` 仍保留为 `Command + Environment.NewLine + DetailTipBody` 的单字符串通路，供自测与读屏使用。
  - 模板改为内联 `ToolTip`：第一段显示完整 `Command`（等宽字体、Accent 色、`TextWrapping=Wrap`），1 px 分隔线后接 `DetailTipBody`；`MaxWidth=720`、内容 `MaxWidth=660`、`ToolTipService.ShowDuration=20000`，长命令换行而不是截断。
  - ToolTip 位于独立 Popup，不继承卡片的 `DataContext`，两段文本都通过 `PlacementTarget.DataContext`（`RelativeSource AncestorType=ToolTip`）取值。
  - 自测断言改为验证"首行完整命令 + 第二段说明"，并覆盖有 `DetailNote` 与只写 `Description` 的两条通路。
- 改动点：`app/Models/ToolItem.cs`、`app/MainWindow.xaml`、`app/Services/SelfTest.cs`、`README.md`、`doc/运行与构建（T0Level）.md`（在线口径，历史实测输出保持原样）、本清单；是否动 `lib/`：否。

## 右栏四角与卡片间距、左栏高亮右缘裁切

- 问题：
  1. 右栏主面板只有上圆角，底部仍是直角。
  2. 左栏 tab 与右侧内容区域贴在一起，看不出是两张独立卡片。
  3. 左栏悬浮/选中灰底右侧两个圆角被裁平；用户疑问“是不是宽度被遮住了”。
- 成因：
  - 右栏 `CornerRadius` 之前只给了上面两角，且两个卡片之间没有边距。
  - 左栏导航项容器宽度绑定的是 `LeftPanelWidth=112`，而 `UI4ListBox` 模板里的 ScrollViewer 自带 4 px 内边距，视口只剩约 103 px；项右侧连同 6 px 圆角一起被 ScrollViewer 裁掉，不是底色遮挡。
- 核心修复方案（宿主层，不动 `lib/`）：
  - 右栏：`CornerRadius=12`（四角）、`Margin=12,0,0,0`（12 px 卡片间距）、`Padding=0,20,0,0`；再给 Border 套 12 px 圆角 `Clip`，把卡片与滚动内容一起裁进圆角轮廓。
  - 左栏：`StyleNavListBoxViewport()` 从 `PART_ListBox`/`PART_BottomListBox` 找到内部 ScrollViewer，把 `Padding` 归零；项位置因此左/上各移 4 px（UIA 实测 `612,400` → `608,396`），悬浮灰底四角恢复。（切主题后这条会被 `UI4ListBox` 的重建冲掉，见下一节。）

- 改动点：`app/MainWindow.xaml.cs`（`StyleNavContentPanel`/`StyleNavLeftRail`/`StyleNavListBoxViewport`/`ApplyRoundedClip`）、`README.md`、`doc/运行与构建（T0Level）.md`、本清单；是否动 `lib/`：否。

## 切主题后左栏悬浮灰底右圆角失效

- 问题：应用启动时，左栏未选中项的悬浮灰底四个圆角正常；在应用内切换明暗主题后，右侧两个角又变回直角。
- 成因（代码级证据）：
  - `UI4ListBox` 构造时把 TextColor / BorderNormalColor / PanelBackground / HoverBackground 挂成资源引用（`lib/UI4ListBox.cs:254-258`）；换主题时这些资源变了，四个 DP 的回调 `OnStyleRefresh` 会执行 `Style = BuildListStyle()`（`lib/UI4ListBox.cs:226-230`）。
  - `BuildListStyle()` 每次新建 ControlTemplate，内部 `ScrollViewer` 又把 `Padding` 写死成 `4,4,4,4`（`lib/UI4ListBox.cs:291`）；旧 ScrollViewer 连同宿主归零的 Padding 一起被替换掉。
  - 宿主此前只在构造与 `Loaded` 调 `StyleNavListBoxViewport()`，之后没有重打，所以换档后 112 px 的项又被约 103 px 的视口裁掉右侧 6 px 圆角。
- 核心修复方案（宿主层，不动 `lib/`）：
  - MainWindow 订阅 `UI4Theme.ThemeChanged`；`OnThemeChanged` 先 `UpdateFooter()`，再用 `Dispatcher.BeginInvoke` 在 `DispatcherPriority.Loaded` 和 `ApplicationIdle` 各调用一次 `ReapplyNavChrome()`。
  - `ReapplyNavChrome()` = `StyleNavContentPanel()` + `StyleNavLeftRail()` + `StyleNavListBoxViewport()`；三个方法内部都会 `ApplyTemplate()`，取不到部件就跳过，因此重复调用是幂等的。
  - `Loaded` 覆盖随主题切换同步发生的 Style/Template 重建；`ApplicationIdle` 兜底晚到的布局/重建。只改宿主，不改 `lib/`。
- 改动点：`app/MainWindow.xaml.cs`（`OnThemeChanged` / `ReapplyNavChrome` / 构造与 `Loaded` 统一走 `ReapplyNavChrome`）、`README.md`（代码地图与 NavigationView 宿主注意项）、`doc/运行与构建（T0Level）.md`（宿主注意项）、本清单；是否动 `lib/`：否。

## 左栏悬浮灰底右侧贴边

- 问题：左栏未选中项的悬浮灰底左侧有内缩，右侧却贴到栏边，左右不对称。
- 成因：库的导航项模板给 `PART_ItemBorder` 只写了 `Margin="2,0,0,0"`——左边 2 px、右边 0；宿主之前把内部 ScrollViewer 的 4 px 内边距归零后，右侧就再没有任何余量，灰底宽度 110 px 一直铺到栏边。
- 核心修复方案（宿主层，不动 `lib/`）：
  - `ApplyNavItemMargins()` 遍历 `PART_ListBox`/`PART_BottomListBox` 已生成的项容器，取 `PART_ItemBorder`，把右边距设为与左边一致（`new Thickness(m.Left, m.Top, m.Left, m.Bottom)`）。项背景宽度变为 112 - 2 - 2 = 108 px，左侧和右侧各留 2 px。
  - 挂 `ItemContainerGenerator.StatusChanged`；虚拟化或换主题重建后新生成的容器会再次补右边距。用 `HashSet<ListBox>` 防止同一个 ListBox 重复挂事件。
  - `StyleNavListBoxViewport()` 统一做“ScrollViewer 内边距归零 + 项右边距补齐”，因此 `OnThemeChanged` 的 Loaded/ApplicationIdle 重打也会带上这次修正。
- 改动点：`app/MainWindow.xaml.cs`（`StyleNavListBox`/`ApplyNavItemMargins`/`_navListBoxesWithMarginHook`）、`README.md`、`doc/运行与构建（T0Level）.md`、本清单；是否动 `lib/`：否。

## 左栏悬浮右侧白边少 1 px

- 问题：左右都设 4 px 后，悬浮灰底左侧可见白边 4 px、右侧可见白边只有 3 px。
- 成因：左栏模板的顶行 Border 有 1 px 右边框（`lib/UI4NavigationView.cs:578`，`Thickness(0,0,1,0)`）；导航项容器宽度仍是 `LeftPanelWidth=112`，但 ListBox 的实际视口只有 111 px。项背景右边缘到视口右界的 4 px margin 中有 1 px 落在被裁边界外，所以可见只有 3 px；左侧没有这个边框，4 px 完整可见。
- 核心修复方案：保留左侧 4 px，新增 `NavItemRightInset = NavItemSideInset + 1`（5 px）；`ApplyNavItemMargins` 使用这个右值。项背景宽度变为 `112 - 4 - 5 = 103 px`，左右可见白边都是 4 px；内容水平中心只左移 0.5 px。原有的容器重生成钩子与主题重打流程自动沿用新值。
- 改动点：`app/MainWindow.xaml.cs`（`NavItemRightInset` / `ApplyNavItemMargins`）、`README.md`、`doc/运行与构建（T0Level）.md`、本清单；是否动 `lib/`：否。

### 验证

- `dotnet build app/QuickPanel.csproj` → 0 个错误 / 0 个警告（增量构建；全量重建时是 9 条固定 lib 警告）。
- `QuickPanel.exe --selftest` → 退出码 0，126 条 `PASS` / 0 条 `FAIL`。
- 按本轮要求不再打开 app 做 UI 验证；1 px 差额由模板的 1 px 右边框与 112/111 px 的容器/视口差直接推出。

## 左栏首个悬浮卡片顶部被栏顶裁切

- 问题：左侧首个未选中项悬浮时，灰底顶边与栏顶重合（顶部内缩为 0），被左栏 12 px 圆角 Clip 切掉。
- 成因：`ApplyNavItemMargins` 之前只补了左右，`PART_ItemBorder` 的上下 Margin 仍是库模板的 0；首个项容器从栏顶 y=0 开始，灰底顶部正好落在栏顶圆角裁切区内。
- 核心修复方案：新增 `NavItemVerticalInset = 4`，项背景上下也留 4 px；上下对称，ContentPresenter 垂直中心不变（图标/文字不移动），首个灰底顶边在 y=4，避开栏顶 12 px 圆角；左右仍 4/5（右 5 补 1 px 右边框）。同一规则也适用于后续项，悬浮卡片之间因此有 8 px 垂直间隔。
- 改动点：`app/MainWindow.xaml.cs`（`NavItemVerticalInset` / `ApplyNavItemMargins`）、`README.md`、`doc/运行与构建（T0Level）.md`、本清单；是否动 `lib/`：否。

### 验证

- `dotnet build app/QuickPanel.csproj` → 0 个错误 / 0 个警告（增量构建；全量重建时是 9 条固定 lib 警告）。
- 按界面显示问题流程未反复打开 app 复现；目测项：首个悬浮灰底顶部出现 4 px 留白，四角不再被栏顶圆角裁切，图标/文字位置不变（上下对称）。

## publish 产物名改为版本 + 模式 + 时间戳

- 问题：两档 publish 一直输出固定名 `QuickPanel_self_contained.exe` / `QuickPanel_no_runtime.exe`，文件名看不出代码版本与构建时间；需求是对齐 `QuickPanel_v1.0.0_<mode>_build_<yyyyMMddHHmmss>.exe`。
- 成因：脚本只靠 `-p:ArtifactLabel=` 生成固定发布工作名，从未读取 csproj 的 `<Version>`，也没有生成构建时间戳/改名步骤。
- 核心修复方案：两个脚本启动时用 `dotnet msbuild QuickPanel.csproj -getProperty:Version -nologo` 读取代码版本（空则失败）；publish 并跑完 selftest 后，用 `Get-Date -Format yyyyMMddHHmmss` 生成时间戳，把固定工作名 `move /y` 成 `QuickPanel_v<Version>_<mode>_build_<timestamp>.exe`。版本不在脚本里手写，改 csproj `<Version>` 即同步。
- 改动点：`publish.cmd`、`publish_no_runtime.cmd`、`README.md`、`doc/运行与构建（T0Level）.md`、本清单；是否动 `lib/`：否。

### 验证

- 实跑 `publish_no_runtime.cmd`：selftest exit 0；产物 `publish_no_runtime\QuickPanel_v1.0.0_no_runtime_build_20261026115457.exe`，1,627,830 B。
- 实跑 `publish.cmd`：selftest exit 0；产物 `publish\QuickPanel_v1.0.0_self_contained_build_20261026115143.exe`，70,420,731 B。
- 两个产物目录各只剩本次时间戳产物；文件名版本 `v1.0.0` 与 csproj `<Version>1.0.0</Version>` 一致。
